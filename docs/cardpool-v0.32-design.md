# v0.32 四流派与指示物卡池

现有56种活动：创意15、技术14、履职14、商业13；每种4份，共224张。逐卡数值见 [卡池表](cards-v0.32.md)。其中12张是跨流派小终端，每个流派3张；只有效果上的分支，没有新增分支标签。

这是可测试的设计稿，不是已经证明平衡的卡池。沿用开局8资金、3理智、工资3、逃离要求副业10且理智6。4h市场8张，8h市场4张，无开局赠牌。

## 收益口径

- `gain.profit`：资金到账，同时计入逃离副业。
- `gain.cash`：只增加资金。加班、卖课、灵感变现、履职奖励、交易所得属于此类。
- 正理智是留场影响，不逐周恢复。支持费用结算前预付；查停失效。支付不起费用的重复牌撤回，成长牌暂停。
- 除概念预售允许使用自己当次3资金购买货品，活动正资金统一周末到账，不能提前支付其他费用。

## 四种指示物

| 指示物 | 所在位置 | 用途与约束 |
|---|---|---|
| 灵感 ✦ | 空置夜晚，可叠放 | 指定活动产生；放牌清空该夜；消耗时选来源；不会自动生成 |
| 自动 ⚙ | 日程卡，每卡最多1 | 每次资金费用减1，最低0；不免查岗；可被跨流派牌消耗 |
| 履职 | 储备或日程卡，每卡最多1 | 安排时可附上免查岗；消耗后失去保护；撤回返还储备 |
| 货品 | 库存或货架 | 打出时库存不足每件付3；交易按牌面单价，撤回时货品回库存 |

自动减免费用优先用于本周预付的支持费，剩余额度用于执行费；每张牌每次合计最多减1。费用已结算后再新增或消耗自动，不重算已付款项。履职保护在掷查岗骰时确定；之后消耗不追溯查岗。

经营卖场有3个货架位，兴趣小店有1个。交易买入时可放入库存或上架，出货可来自库存或货架。撤回时货品回库存。周末加总本周成功执行的牌。动态副业按算账时桌上仍在的指示物计算。

## 相邻与归档

版图按周一至周日为列、上午/下午/夜晚为行。相邻只认接触的格，空格不能跳过。8h覆盖上午、下午；其右邻可有两个目标，选择一个；下邻为当日夜晚。数据收集先执行，在下邻成功执行时加2副业；查停或未执行不获益。

成长每次成功执行推进1，费用、条件或指示物不足不推进。效果在每次执行发生，只有明确“完成”的奖励在末次发生。所有完成牌进入归档区，同名技能只计一次，卖课按实物张数计数。自动管线可从归档区再次安排，先离开归档并重置进度。招聘只从市场取得其他流派成长，费用为买价＋全程执行费＋1，不执行目标收益或完成奖励；实际招募才推进。

## 循环与交叉终端

| 主流派 | 内部循环 | 三张交叉终端 |
|---|---|---|
| 创意 | 空夜积累灵感 → 集中变现/日常写作；采风找牌；签约和艺人转稳定副业 | 带薪驻留消耗履职，提供理智与副业；自费出版消耗货品，提供3副业；作品发行消耗自动，变现5资金 |
| 技术 | 学习归档 → 相邻自动/数据加成；订阅产品成熟；Agent汇总自动牌 | 企业试点消耗履职并给右邻自动；云端托管打出付3资金，每次计2副业；创意原型逐次消耗灵感产3副业 |
| 履职 | 加班换现金；工作成长换履职；授权保护摸鱼或争取双休 | 提案汇报消耗灵感；垫资推进打出付3资金；流程验收消耗自动，均转现金/履职 |
| 商业 | 交易买卖货品；货架按上架货品计副业；招聘跨流派归档 | 概念预售灵感变现后可买货品；自动补货两格上满且有自动时额外计1副业；企业团购打出消耗货品，牌面副业3 |

## 三归档终端

| 卡 | 购买技能 | 发动条件和结果 |
|---|---|---|
| 流窜艺人 | AAA | 打出时，从自己每个有灵感的空夜各移1枚到本牌。基础副业2，牌上每枚灵感再计1副业。灵感跨周保留，撤回时移除。 |
| Agent商业化 | BBB | 理智≥4。基础副业2，每张带自动的牌加1（最多加2）。执行时给下邻放1自动，能直接支援当晚的活动。 |
| 经营卖场 | CCC | 基础副业1，每件上架货品加1。满架可卖1件得4资金。周末剩两件计3副业，留三件计4。 |
| 创意原型 | AAB | 消耗1灵感，副业3；本牌带自动时计4。理智≥6抽1张I级；同时有自动则改为看3张I级，免费选1张满足技能的牌。 |
| 自动补货 | BCC | 本牌带自动时，成功执行先免费补1件到空货架再计副业；满架且有自动额外+1。空架启动第一周2、第二周4。 |

## 待试玩验证

重点比较基础2副业牌与技能/指示物投资的回本速度；检查自动管线反复归档、卖课与招聘是否积累资金过快；检测免查岗覆盖后能否缺少生活支持也稳定逃离。规则检查不能替代真人平衡测试。

## 数据与编辑

为兼容卡牌工坊及本地API，主数据路径保留 `data/cardpool-v31.json`，内部版本为32。`npm run generate` 同步运行时数据和新版卡池表；`scripts/create-v32-pool.mjs` 是一次性迁移脚本，不参与日常构建，后续编辑不得重跑覆盖。工坊的基本数值直接编辑，特殊指示物规则在完整卡牌JSON的 `mechanic` 中编辑。旧版牌表仅作历史记录。

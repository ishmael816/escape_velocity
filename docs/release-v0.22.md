# v0.22 完整卡池重设计与验证

本次不是删除17张2h后保留其余旧数值：全部卡池改为32种，23种4h、9种8h，采用新ID及独立存档。起始8现金/3理智、工资3、逃离10副业/6理智保持不变。

## 设计与实现

- 每路线两个不同名成长；入门4h买价1，第二成长买2返1；四种中阶、八种高级/混合牌重新核算收益、压力、支持、本金与技能。
- 夜间一张4h，压力2、支持照常生效；标准支持2放夜间净理智0。并行只允许白天两张4h，8h独占全天。
- 商业固定本金，撤回返还；移除灵感、活动骰、下一张加成、条件奖金和自由本金份额。
- 共享一次性“寻找机会”看3买1；招募改为4h成长、目标原价+1，不执行返现。双休两周各付1、不再要求先成功副业。
- 市场4h/8h展示6/4。普通每种N张、高级每种ceil(N/2)张。终局排名及逃离后操作规则未扩展。
- 唯一数据源[data/cardpool-v22.json](../data/cardpool-v22.json)；`npm run generate`同步运行卡池与[完整牌表](cards-v0.22.md)。构建先检查生成一致性；旧导出器阻止覆盖新版。
- `escape-velocity-game-v22`独立存档，v21存档不读取、不删除。页面帮助、卡面、资源栏和找牌界面同步更新。

## 已运行的验证

- 新版53项自动测试通过，含14个具体构筑在真实引擎中的安排、收入、理智、本金、维护核对；以及市场实际购买、不同名成长归档、费用不足、存档键、搜索断点续局、招聘、夜间和并行边界。
- 原132项针对旧卡ID和旧规则的测试移入`tests/legacy-v21`保留；它们不是新版53项的组成部分，也没有宣称旧132项能验证新规则。
- 生成一致性、JavaScript语法和静态构建通过。DOM契约测试验证首页、图鉴、帮助、设置可以渲染；它不是浏览器视觉QA。
- [九局现有启发式机器人](simulation-economy-v0.22.json)：2/3/4人、三个种子，全部结束，5–13周。仅证明这些策略能合法推进。
- [27局重复基础策略对比](strategy-comparison-v0.22.json)：每局一名“廉价、同名重复、零技能”策略对阵现有成长启发式，轮换全部座位，三个相同种子、2/3/4人。全部结束；基础策略16局逃离，6局最先或并列最先。该批记录中逃离时：基础策略9–12张在场活动，成长启发式3–10张；不能据此保证每局都只有3–6张。不能解释为真人胜率或最优策略胜率。
- [独立静态预算](static-balance-v0.22.json)：全部高级门槛有足够不同名来源；无技能、无限现金、无查岗、允许拿走全场同名供给时，2人至少8张活动、3/4人至少7张。所有同名支持完整相加，没有通过递减或牌数上限取得这一结果。

## 仍需实玩评估

零技能便宜铺牌仍是合法路径：四人供应下，十张基础/支持牌只需购价13加首周维护2即可在无查岗时达线，代价是20个买/排操作、12个白天半槽与持续维护。成长示例常驻3–6张，但归档、权限、筹资与获牌时间必须真实支付。

本机浏览器控制库存为空，创建内置浏览器返回“Browser is not available: iab”。因此本报告不声称已完成浏览器实玩或视觉验收。线上构建通过`version.json`暴露公开版本/提交SHA，便于发布后核验；真实网页操作与主观游玩体验需另行记录，不能把上述静态/自动结果冒充真人试玩。

优先观察：开发第一次成长是否兑现偏慢，职场双休是否过强，商业锁本是否易卡现金，搜索的两次买/排动作是否值得，低价基础抢跑是否仍过于稳定。
